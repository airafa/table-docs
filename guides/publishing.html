Publishing the documentation ​

Anonymized examples and search-engine policy ​

All documentation uses anonymized company and library names, including package names, custom-element tags, and URLs inside code examples. These names are placeholders: the published examples are not directly runnable without mapping them back to the real private dependencies. Imported source blocks are anonymized during syntax highlighting; the application source is not renamed. The same warning appears in the footer of every page.

Every generated HTML page, including the custom 404 page, carries noindex, nofollow, noarchive metadata for general crawlers and Googlebot. A robots.txt file requests that crawlers do not crawl the site. Since this is a GitHub Pages project site, /table-docs/robots.txt is not the authoritative host-level /robots.txt; the page-level noindex directives provide the indexing policy independently of that file.

These are requests to cooperative search engines, not authentication or a privacy boundary. They cannot guarantee that the site never appears in search results, remove already indexed URLs immediately, stop noncompliant crawlers, or hide the public repository. Existing indexed results may require removal requests through the search engine's webmaster tools. Use private hosting with authentication if the content must be inaccessible publicly.

The workflow runs node tools/verify-docs.mjs before publishing. It checks all built HTML, JavaScript, JSON, CSS, and other text assets for unredacted names, and verifies the indexing metadata and crawler file. A failure prevents deployment and preserves the previous public site.

The public documentation lives at https://airafa.github.io/table-docs/. The public airafa/table-docs repository contains only the generated VitePress site, including the rendered code examples. The application source remains in the private source repository.

Deployment flow ​

  1. A pull request builds the documentation and checks internal links.
  2. A push to main builds and publishes the generated site. Changes to source files also trigger a build because the tutorial imports those files as code examples.
  3. GitHub Pages serves the public repository's main branch at its root. The generated .nojekyll file disables Jekyll processing.

You can also run Publish documentation manually from the source repository's Actions tab. Manual runs publish only when the selected branch is main.

The workflow installs only the locked public dependencies in docs/package.json. It does not install the application's private packages or need a private registry token. The checked-in docs/package-lock.json is maintained with:

sh
npm install --prefix docs --workspaces=false --package-lock-only

The workflow sets DOCS_BASE=/table-docs/ so links, scripts, styles, and local search work under the GitHub Pages project path. Local development defaults to /. To reproduce the deployed build:

sh
npm ci --prefix docs --workspaces=false
DOCS_BASE=/table-docs/ npm --prefix docs run build
npm --prefix docs run preview -- --host 127.0.0.1

Open the preview's /table-docs/ path, not its root.

Deployment credentials ​

The source repository's DOCS_DEPLOY_KEY Actions secret is an SSH private key. Its public half is a write-enabled deploy key on airafa/table-docs only. It does not grant access to other repositories. Pull requests never run the deployment step, and checkout does not persist its GitHub token.

To rotate the key:

  1. Generate a new dedicated Ed25519 SSH key pair.
  2. Add its public half to Settings > Deploy keys in airafa/table-docs, enabling write access.
  3. Replace the source repository's DOCS_DEPLOY_KEY Actions secret with the private half.
  4. Run the workflow on main and verify the site.
  5. Remove the old deploy key and securely remove local private-key files.

Never commit either a private key or an access token.

Verification and troubleshooting ​

  • Check Publish documentation in the private source repository's Actions tab.
  • Check the Pages deployment in the public repository's Actions tab.
  • Verify the home page, a tutorial chapter, navigation, and local search at https://airafa.github.io/table-docs/.
  • A build failure does not replace the last successful public site.
  • A deployment permission failure usually means the deploy key is missing, revoked, or does not have write access.
  • A missing stylesheet or broken navigation usually indicates an incorrect DOCS_BASE; use /table-docs/ for this repository.
  • If GitHub Pages is disabled, configure deployment from branch main, folder /, in the public repository's Settings > Pages.

Publishing exposes the built documentation, including embedded source examples and configuration. Review new content for public suitability before merging.
