1. Install and run ​

Step 1: Open the monorepo root ​

A monorepo holds multiple packages in one repository. Yarn workspaces connect them, so run package-manager commands at the root, not inside a module.

sh
cd lc-application-starterkit-dnd
node --version
yarn --version

This project's root requires Node 18 or newer and Yarn 1.22.19. Use an available supported Node release that satisfies the packages' engines. This walkthrough was validated with the environment's Node 24. If Yarn is missing, install the version the repository requires:

sh
npm install --global yarn@1.22.19

Step 2: Get access to lc packages ​

@lc/graphs and the other lc packages come from the organization's package registry. Use your organization's normal authentication process. Do not copy tokens into source code, examples, or documentation.

Inspect the configured scope and package version:

sh
npm config get @lc:registry
npm view @lc/graphs@0.0.1-rc30 version

Checkpoint: the second command prints 0.0.1-rc30. A 401, 403, or registry/network failure is an access problem, not a React problem. Fix registry access before continuing.

Step 3: Understand the dependency placement ​

DependencyWhere it belongsWhy
@tanstack/react-table@9.3.1packages/design-system/tablev9 renderer owns the engine
@tanstack/react-table@8.21.3packages/design-system/table-v8Existing v8 renderer stays isolated
@lc/graphs@0.0.1-rc30appApplication registers the web components
React / React DOM 19.3.1Application/module dependencies and table peersBoth table engines share one React runtime
React Redux 9.3.1Application and Redux-backed modulesSupports React 19
vitepress@1.6.4docs workspace dev dependenciesDocumentation only

Do not install one table version at the root and force every consumer to use it. Do not add a Yarn resolutions entry overriding all TanStack packages.

The React runtime uses the latest stable npm release verified for this upgrade. React types are pinned to @types/react@19.2.17 and @types/react-dom@19.2.3, the latest releases compatible with this project's TypeScript 5.3 compiler. Newer type releases require TypeScript 5.6; upgrading the compiler is a separate task.

For an adaptation where the dependencies are not already declared, the workspace commands are:

sh
yarn workspace @starterkit/table add @tanstack/react-table@9.3.1 --exact
yarn workspace @starterkit/app add @lc/graphs@0.0.1-rc30 --exact

In this checkout they are already declared; simply install:

sh
yarn install

The registry's latest tag was still 0.0.1-rc9 when this implementation was written; the rc tag pointed to 0.0.1-rc30. Pinning the inspected version avoids silently switching APIs.

Step 4: Keep the two table versions separate in Vite development ​

Vite prebundles dependencies to speed up development. In this dual-version workspace, prebundling both table majors as if they were one package can serve the wrong engine to a consumer.

The existing config excludes the table engines from optimization and explicitly includes the React Store adapter needed by v9. Keep this configuration while the v8/v9 comparison exists.

Complete Vite configuration ​

ts
import { defineConfig } from 'vite';
import react from '@vitejs/plugin-react';

export default defineConfig({
  base: "",
  publicDir: 'static',
  optimizeDeps: {
    exclude: ['@tanstack/react-table', '@tanstack/table-core'],
    include: ['@tanstack/react-store'],
  },
  build: {
    sourcemap: true,
    outDir: 'dist',
  },
  plugins: [
    react({ include: /\.(js|jsx|ts|tsx)$/ }),
  ],
  esbuild: {
    loader: 'tsx',
    include: [
      "src/**/*.js",
      "src/**/*.ts",
      "src/**/*.jsx",
      "src/**/*.tsx",
      "../modules/**/src/**/*.js",
      "../modules/**/src/**/*.ts",
      "../modules/**/src/**/*.jsx",
      "../modules/**/src/**/*.tsx",
      "../packages/**/src/**/*.js",
      "../packages/**/src/**/*.ts",
      "../packages/**/src/**/*.jsx",
      "../packages/**/src/**/*.tsx",
    ]
  }
})

Step 5: Run the application ​

sh
yarn dev

Open the URL Vite prints. The port may differ if another server already uses the default. You should see two tables above the map, not a separate demo HTML page.

Checkpoint: both table titles are visible. If only v8 appears, check whether VITE_TABLE_POC_STAGE=v8 is set. If neither appears, check for baseline. The default enables both; restart Vite after changing environment variables.

Step 6: Run this documentation site ​

In another terminal at the root:

sh
yarn docs:dev

Open the documentation URL printed in that terminal. Use the sidebar for the chapters, the page outline for individual steps, and the search button for symbols such as GanttHeader, rowHeight, or resizable.

To check the static site:

sh
yarn docs:build
yarn docs:preview

Generated files live under docs/.vitepress/dist and are ignored by Git. The application and documentation have separate commands: yarn build builds the app; yarn docs:build builds the guide.

Before moving on ​

  • Yarn installation succeeds using the private registry.
  • The main app opens with both modules.
  • The documentation opens with a sidebar and local search.
  • You know which workspace owns each engine.
