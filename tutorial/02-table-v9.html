2. Build the TanStack v9 table ​

Step 1: Know what a headless table does ​

TanStack is headless: it computes rows and columns but does not choose your HTML, colors, or canvas layout. The design system supplies the actual table, thead, tbody, th, and td elements.

Three terms appear throughout the code:

  • Data: your array of records.
  • Column definition: which property to display and how to render it.
  • Row model: the current ordered list after operations such as sorting.

Step 2: Create the engine-owning workspace ​

Complete v9 package manifest ​

json
{
  "name": "@starterkit/table",
  "version": "0.0.0",
  "private": true,
  "type": "module",
  "main": "src/index.tsx",
  "dependencies": { "@tanstack/react-table": "9.3.1" },
  "peerDependencies": { "react": "19.3.1", "react-dom": "19.3.1" }
}

main points to TypeScript source because this starter kit's Vite build consumes workspace source directly. This is not a recipe for publishing an unbuilt package to arbitrary external consumers.

The root's workspaces list includes the nested packages/design-system/table and packages/design-system/table-v8 directories. Without those entries, the root's packages/* pattern would only discover their parent.

Step 3: Register sorting using the installed v9 API ​

The important v9 setup is:

tsx
import {
  createSortedRowModel,
  rowSortingFeature,
  sortFns,
  tableFeatures,
  useTable,
} from '@tanstack/react-table';

const features = tableFeatures({
  rowSortingFeature,
  sortedRowModel: createSortedRowModel(),
  sortFns,
});

This is not v8's useReactTable setup. The feature set determines the available APIs and types. The implementation uses the built-in sort-function registry for this comparison; a smaller production package can register only the sort functions it actually needs.

The exported column type binds the feature set once:

tsx
import type {
  ColumnDef as TanStackColumnDef,
  RowData,
} from '@tanstack/react-table';

export type ColumnDef<TData extends RowData> =
  TanStackColumnDef<typeof features, TData>;

Consumers can now write ColumnDef<Asset> rather than repeating the feature parameter. Do not pass the v8 workspace's column types into v9.

Step 4: Render the row model ​

In the complete implementation below:

  1. useTable receives the feature set, records, column definitions, and options.
  2. getHeaderGroups() creates the header rows.
  3. Header buttons call the column's sorting handler.
  4. getRowModel().rows returns the sorted records.
  5. table.FlexRender renders the column's React header/cell definition.
  6. Stable row IDs become React keys, so replacing objects does not automatically replace the existing DOM.

onRender measures only this React component's start-to-layout-effect interval. The later work performed by custom elements is not included in that number.

Complete v9 renderer ​

Create or inspect packages/design-system/table/src/index.tsx:

tsx
import { createSortedRowModel, rowSortingFeature, sortFns, tableFeatures, useTable } from '@tanstack/react-table';
import type { ColumnDef as TanStackColumnDef, RowData, TableOptions } from '@tanstack/react-table';
import { useLayoutEffect } from 'react';
import '../../src/table.css';
import { useTableWindow } from '../../src/useTableWindow';

export const features = tableFeatures({ rowSortingFeature, sortedRowModel: createSortedRowModel(), sortFns });
export type ColumnDef<TData extends RowData> = TanStackColumnDef<typeof features, TData>;

export type TableProps<TData extends RowData> = {
  data: TData[];
  columns: ColumnDef<TData>[];
  options?: Partial<Omit<TableOptions<typeof features, TData>, 'features' | 'data' | 'columns'>>;
  onRender?: (durationMs: number) => void;
  rowHeight?: number;
};

export function Table<TData extends RowData>({ data, columns, options, onRender, rowHeight }: TableProps<TData>) {
  const started = performance.now();
  useLayoutEffect(() => { onRender?.(performance.now() - started); });
  const table = useTable({ ...options, features, data, columns });
  const rows = table.getRowModel().rows;
  const window = useTableWindow(rows.length, rowHeight);
  return <div className="ds-table-scroll" ref={window.scrollRef}><table className="ds-table" data-row-count={rows.length} aria-rowcount={rows.length + 1}>
    <thead ref={window.headerRef}>{table.getHeaderGroups().map(group => <tr key={group.id}>{group.headers.map(header => <th key={header.id} aria-sort={header.column.getIsSorted() === 'asc' ? 'ascending' : header.column.getIsSorted() === 'desc' ? 'descending' : 'none'}>
      {header.isPlaceholder ? null : header.column.getCanSort() ? <button type="button" onClick={header.column.getToggleSortingHandler()}><table.FlexRender header={header} />{header.column.getIsSorted() === 'asc' ? ' + ' : header.column.getIsSorted() === 'desc' ? ' - ' : ''}</button> : <table.FlexRender header={header} />}
    </th>)}</tr>)}</thead>
    <tbody>
      {window.before > 0 && <tr aria-hidden="true"><td colSpan={columns.length} style={{ height: window.before, padding: 0, border: 0 }} /></tr>}
      {rows.slice(window.start, window.end).map((row, index) => <tr key={row.id} data-row-id={row.id} aria-rowindex={window.start + index + 2} style={rowHeight ? { height: rowHeight } : undefined}>{row.getAllCells().map(cell => <td key={cell.id}><table.FlexRender cell={cell} /></td>)}</tr>)}
      {window.after > 0 && <tr aria-hidden="true"><td colSpan={columns.length} style={{ height: window.after, padding: 0, border: 0 }} /></tr>}
    </tbody>
  </table></div>;
}

Step 5: Avoid mounting thousands of Gantt charts ​

Each Gantt row owns a canvas and rendering loop. Rendering 1,000 table rows therefore has a much higher cost than rendering 1,000 plain text rows.

The optional rowHeight prop enables a small fixed-height row window:

tsx
<Table
  data={data}
  columns={columns}
  rowHeight={49}
  options={{ getRowId: row => String(row.id) }}
/>

The table still computes sorting for all records. Only visible rows plus overscan become DOM rows. Spacer rows preserve the space occupied by records above and below them.

Complete shared window hook ​

Create or inspect packages/design-system/src/useTableWindow.ts:

ts
import { useLayoutEffect, useRef, useState } from 'react';

export function useTableWindow(count: number, rowHeight?: number) {
  if (rowHeight !== undefined && (!Number.isFinite(rowHeight) || rowHeight <= 0)) {
    throw new Error('rowHeight must be a positive finite number');
  }
  const scrollRef = useRef<HTMLDivElement>(null);
  const headerRef = useRef<HTMLTableSectionElement>(null);
  const [viewport, setViewport] = useState({ top: 0, height: 320, header: 114 });
  useLayoutEffect(() => {
    const scroll = scrollRef.current;
    const header = headerRef.current;
    if (!rowHeight || !scroll || !header) return;
    const measure = () => setViewport(previous => {
      const next = { top: scroll.scrollTop, height: scroll.clientHeight, header: header.offsetHeight };
      return previous.top === next.top && previous.height === next.height && previous.header === next.header ? previous : next;
    });
    const observer = new ResizeObserver(measure);
    observer.observe(scroll);
    observer.observe(header);
    scroll.addEventListener('scroll', measure, { passive: true });
    measure();
    return () => {
      observer.disconnect();
      scroll.removeEventListener('scroll', measure);
    };
  }, [rowHeight]);
  const visible = rowHeight ? Math.ceil(Math.max(0, viewport.height - viewport.header) / rowHeight) + 8 : count;
  const start = rowHeight ? Math.min(Math.max(0, count - visible), Math.max(0, Math.floor(viewport.top / rowHeight) - 4)) : 0;
  const end = Math.min(count, start + visible);
  return { scrollRef, headerRef, start, end, before: start * (rowHeight ?? 0), after: (count - end) * (rowHeight ?? 0) };
}

Walk through the arithmetic ​

For a 320px scroll viewport and roughly 114px header:

text
body space       = 320 - 114 = 206px
visible records  = ceil(206 / 49) = 5
mounted records  = 5 + 8 overscan = 13
start index      = floor(scrollTop / 49) - 4, clamped to valid bounds
top spacer       = start index * 49
bottom spacer    = unmounted records below the window * 49

The hook observes the real viewport and header rather than relying permanently on the initial estimates. Scrolling updates the window; unmounting old charts lets the package clean up their observers and loops.

Fixed height is a real contract

The demo's 32px Gantt canvas plus 8px top/bottom cell padding and a 1px border produces a 49px row. If you change padding or allow text to wrap, measure the actual row and update rowHeight. This helper does not support variable-height rows. A wrong height causes scroll gaps and wrong visible ranges.

Omitting rowHeight preserves the old render-all-rows behavior. Offscreen records are not in the DOM for browser find or screen-reader browsing until scrolled into view. Total count and logical row indexes are exposed with ARIA attributes; this does not remove that limitation.

Step 6: Keep the v8 comparison working ​

The v8 renderer uses useReactTable, getCoreRowModel, getSortedRowModel, and flexRender. It shares only the engine-independent window hook and CSS.

Complete v8 renderer ​

tsx
import { flexRender, getCoreRowModel, getSortedRowModel, useReactTable } from '@tanstack/react-table';
import type { ColumnDef, TableOptions } from '@tanstack/react-table';
import { useLayoutEffect } from 'react';
import '../../src/table.css';
import { useTableWindow } from '../../src/useTableWindow';

export type { ColumnDef } from '@tanstack/react-table';

export type TableProps<TData> = {
  data: TData[];
  columns: ColumnDef<TData, any>[];
  options?: Partial<Omit<TableOptions<TData>, 'data' | 'columns'>>;
  onRender?: (durationMs: number) => void;
  rowHeight?: number;
};

export function Table<TData>({ data, columns, options, onRender, rowHeight }: TableProps<TData>) {
  const started = performance.now();
  useLayoutEffect(() => { onRender?.(performance.now() - started); });
  const table = useReactTable({ getCoreRowModel: getCoreRowModel(), getSortedRowModel: getSortedRowModel(), ...options, data, columns });
  const rows = table.getRowModel().rows;
  const window = useTableWindow(rows.length, rowHeight);
  return <div className="ds-table-scroll" ref={window.scrollRef}><table className="ds-table" data-row-count={rows.length} aria-rowcount={rows.length + 1}>
    <thead ref={window.headerRef}>{table.getHeaderGroups().map(group => <tr key={group.id}>{group.headers.map(header => <th key={header.id} aria-sort={header.column.getIsSorted() === 'asc' ? 'ascending' : header.column.getIsSorted() === 'desc' ? 'descending' : 'none'}>
      {header.isPlaceholder ? null : header.column.getCanSort() ? <button type="button" onClick={header.column.getToggleSortingHandler()}>{flexRender(header.column.columnDef.header, header.getContext())}{header.column.getIsSorted() === 'asc' ? ' + ' : header.column.getIsSorted() === 'desc' ? ' - ' : ''}</button> : flexRender(header.column.columnDef.header, header.getContext())}
    </th>)}</tr>)}</thead>
    <tbody>
      {window.before > 0 && <tr aria-hidden="true"><td colSpan={columns.length} style={{ height: window.before, padding: 0, border: 0 }} /></tr>}
      {rows.slice(window.start, window.end).map((row, index) => <tr key={row.id} data-row-id={row.id} aria-rowindex={window.start + index + 2} style={rowHeight ? { height: rowHeight } : undefined}>{row.getVisibleCells().map(cell => <td key={cell.id}>{flexRender(cell.column.columnDef.cell, cell.getContext())}</td>)}</tr>)}
      {window.after > 0 && <tr aria-hidden="true"><td colSpan={columns.length} style={{ height: window.after, padding: 0, border: 0 }} /></tr>}
    </tbody>
  </table></div>;
}

Do not replace the imports above with v9 imports. Keeping two small wrappers is clearer than inventing a universal table instance type across incompatible majors.
