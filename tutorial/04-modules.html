4. Wire data, columns, and application modules ​

Step 1: Define one record shape ​

The shared demo record is:

ts
type RecordRow = {
  id: number;
  name: string;
  status: string;
  amount: number;
  tasks: GanttItem[];
};

The ID identifies an asset. Task IDs identify its ranges and milestone. Refreshing changes values and object references, not these identities. Using array positions as row IDs would attach existing UI state to the wrong record after sorting or reordering.

Step 2: Generate predictable mock snapshots ​

The demo generates 100 records initially and offers 1,000 or 5,000. For each revision:

  • Status cycles between Active/Pending/Offline.
  • Amount changes deterministically.
  • The task start moves by three days within a bounded cycle.
  • Plan lasts 4 days, Build 8 days, and Verify 6 days.
  • A point marks completion.

Predictable data makes regressions easier to reproduce than random timestamps. Refresh data replaces the array, each record object, and the task arrays. The row components' effects see the new references and assign new DOM data.

Complete shared demo and data generator ​

Create or inspect modules/module-table-v8/src/demo.tsx:

tsx
import { useLayoutEffect, useRef, useState } from 'react';
import type { ReactNode } from 'react';
import { GanttDemo, type GanttItem } from './gantt';

export type RecordRow = { id: number; name: string; status: string; amount: number; tasks: GanttItem[] };
export type RenderSample = { version: string; rows: number; durationMs: number; recordedAt: number };

declare global {
  interface Window { __TABLE_POC_METRICS__?: RenderSample[] }
}

export function TableDemo({ version, children }: {
  version: string;
  children: (data: RecordRow[], onRender: (durationMs: number) => void) => ReactNode;
}) {
  const [count, setCount] = useState(100);
  const [revision, setRevision] = useState(0);
  const output = useRef<HTMLOutputElement>(null);
  const updateOutput = useRef<HTMLOutputElement>(null);
  const updateStarted = useRef<number | null>(null);
  const [data, setData] = useState(() => makeRows(100, 0));
  const replaceRows = (rows: number) => {
    updateStarted.current = performance.now();
    setCount(rows);
    setRevision(revision + 1);
    setData(makeRows(rows, revision + 1));
  };
  useLayoutEffect(() => {
    if (updateStarted.current === null) return;
    let second = 0;
    const first = requestAnimationFrame(() => {
      second = requestAnimationFrame(() => {
        if (updateStarted.current === null) return;
        const duration = performance.now() - updateStarted.current;
        if (updateOutput.current) updateOutput.current.textContent = `Input to next frame: ${duration.toFixed(2)} ms | ${count} records (visible rows mounted)`;
        performance.measure(`table-${version}-input-to-frame`, { start: updateStarted.current, duration });
        updateStarted.current = null;
      });
    });
    return () => { cancelAnimationFrame(first); cancelAnimationFrame(second); };
  }, [data, count, version]);
  const record = (durationMs: number) => {
    const samples = window.__TABLE_POC_METRICS__ ??= [];
    samples.push({ version, rows: count, durationMs, recordedAt: performance.now() });
    if (output.current) output.current.textContent = `React render to commit: ${durationMs.toFixed(2)} ms | ${count} records (excludes later canvas work)`;
    performance.measure(`table-${version}-render-to-commit`, { start: performance.now() - durationMs, duration: durationMs });
  };
  return <section className="table-poc-module" data-table-version={version} onClick={event => event.stopPropagation()}>
    <GanttDemo data={data} toolbar={<>
      <h2>TanStack Table {version}</h2>
      <div className="table-poc-row-controls">
      <label>Rows <select aria-label={`${version} row count`} value={count} onChange={event => replaceRows(Number(event.target.value))}>
        {[100, 1000, 5000].map(rows => <option key={rows} value={rows}>{rows}</option>)}
      </select></label>
      <button type="button" onClick={() => replaceRows(count)}>Refresh data</button>
      <span role="status">Timeline revision: {revision}</span>
      </div>
    </>}>{children(data, record)}</GanttDemo>
    <output className="table-poc-metrics" ref={output} aria-live="polite" />
    <output className="table-poc-update-metrics" ref={updateOutput} aria-live="polite" />
  </section>;
}

function makeRows(count: number, revision: number): RecordRow[] {
  const day = 86400000;
  const epoch = Date.parse('2026-10-01T00:00:00Z');
  return Array.from({ length: count }, (_, index) => {
    const start = epoch + ((index * 7 + revision * 3) % 13) * day;
    return {
      id: index + 1,
      name: `Asset ${String(index + 1).padStart(4, '0')}`,
      status: ['Active', 'Pending', 'Offline'][(index + revision) % 3],
      amount: ((index * 37 + revision * 13) % 10000) / 100,
      tasks: [
        { id: `${index + 1}-plan`, type: 'range', name: 'Plan', date: [start, start + 4 * day], color: '#16a34a' },
        { id: `${index + 1}-build`, type: 'range', name: 'Build', date: [start + 4 * day, start + 12 * day], color: '#2563eb' },
        { id: `${index + 1}-verify`, type: 'range', name: 'Verify', date: [start + 12 * day, start + 18 * day], color: '#d97706' },
        { id: `${index + 1}-milestone`, type: 'point', name: `Asset ${index + 1} milestone`, date: start + 18 * day, color: '#2563eb' },
      ],
    };
  });
}

Understand the two timing outputs ​

React render to commit is the table's component timing. It excludes later canvas work.

Input to next frame starts before generating the replacement data and ends at a second animation-frame callback after commit. This gives the browser a frame opportunity but does not prove that the display has presented every pixel. Both values are milliseconds, not nanoseconds.

The callbacks write to output refs rather than updating React state merely to display performance text, which avoids a measurement-triggered rerender loop.

Step 3: Define v9 columns ​

The first four columns read simple record fields. The final column is a display column: it has an explicit id, a React header, and a React cell, not an accessorKey.

tsx
{
  id: 'timeline',
  header: () => <GanttHeader />,
  cell: ({ row }) => <GanttCell tasks={row.original.tasks} />,
}

row.original is the original asset record. Its task list is rendered in the same row after sorting; no separate chart row-order synchronization is needed. Because the timeline is a display column, it has no automatic value-based sort.

Complete v9 module ​

Create or inspect modules/module-table/src/module.index.tsx:

tsx
import EditableModule from '@starterkit/module-editable-module';
import { Table, type ColumnDef } from '@starterkit/table';
import { TableDemo, type RecordRow } from '../../module-table-v8/src/demo';
import { GanttCell, GanttHeader } from '../../module-table-v8/src/gantt';

const columns: ColumnDef<RecordRow>[] = [
  { accessorKey: 'id', header: 'ID' },
  { accessorKey: 'name', header: 'Asset' },
  { accessorKey: 'status', header: 'Status' },
  { accessorKey: 'amount', header: 'Amount' },
  { id: 'timeline', header: () => <GanttHeader />, cell: ({ row }) => <GanttCell tasks={row.original.tasks} /> },
];

export default class Module extends EditableModule {
  mount() {
    super.mount();
    this.render();
  }

  render() {
    return <TableDemo version="v9.3.1">{(data, onRender) => <Table data={data} columns={columns} rowHeight={49} options={{ getRowId: row => String(row.id) }} onRender={onRender} />}</TableDemo>;
  }
}

The module extends the starter kit's EditableModule, calls its normal mount behavior, then returns the React demo. It supplies:

tsx
rowHeight={49}
options={{ getRowId: row => String(row.id) }}

The stable row ID preserves identity. The fixed height bounds mounted canvases. The column array is defined outside the component so it is not rebuilt on every refresh.

Step 6: Follow application startup ​

The startup path is:

text
app/src/index.ts imports index.define.ts
  -> registers lc-gantt and children
app initialization loads general.json and modules.json
  -> installs module resolver using loadModule()
  -> creates layout containers
startup creates modules whose config has init: true
  -> module resolver dynamically imports module-table / module-table-v8
  -> module-created handler adds each to its named container
  -> Layout and Panel render web-module hosts

Complete application entrypoint ​

ts
import { createModule, getConfig } from "@lc/baseplate";
import { store } from "./store";
import init from "./index.init";
import render from "./index.render";
import "./index.define";
import "./studio";
import "./index.css";
import "../static/assets/themes/index.dark.css";

store.subscribe(render);

const getInitModules = () => {
  const modules = getConfig("modules");

  return Object.keys(modules).filter((moduleName) => modules[moduleName].init);
};

(async function main() {
  try {
    await init();

    const splashElement = document.getElementById("splash");
    splashElement?.remove();

    render();

    getInitModules().forEach((moduleName) => createModule(moduleName));

    console.log("Application: loaded");
  } catch (ex) {
    console.error("Error: Application: loaded", ex);
  }
})();

Complete initialization wiring ​

ts
import { LayoutElementTypeEnum, ModuleConfig } from "@starterkit/types";
import {
  setModulesResolver,
  setConfig,
  getConfig,
  loadLanguages,
  init,
  onLocalization,
  dir,
  onModuleCreated,
  onModuleRemoved,
  t,
  registerTopic,
} from "@lc/baseplate";
import { loadConfigs } from "./assetsLoader";
import { loadModule } from "./moduleLoader";
import { store } from "./store";
import { setDevMode } from "./store/slices/modules";
import { initialize } from "./store/sharedActions";
import { DEV_MODE_TOGGLED } from "@starterkit/topics";
import { addLayout, addModule, removeModule } from "@starterkit/layout";

setModulesResolver(async (moduleConfig: ModuleConfig) => {
  const started = performance.now();
  const module = await loadModule(moduleConfig.module);
  performance.measure(`module-import:${moduleConfig.module}`, { start: started, duration: performance.now() - started });
  return module.default;
});

onModuleCreated((uuid: string, config: ModuleConfig) => {
  addModule(config.container, {
    name: config.name,
    config,
    uuid,
    layoutElementType: LayoutElementTypeEnum.MODULE,
  });
});

onModuleRemoved((uuid: string, config: ModuleConfig) => {
  removeModule(config.container, uuid);
});

const initLocalization = () => {
  const urlParams = new URLSearchParams(window.location.search);
  const langParm = urlParams.get("lang");
  const { general, languages, modules } = getConfig();
  const sideNavIcons = Object.keys(modules)
    .filter(
      (moduleName) =>
        modules[moduleName].container === "side-panel" &&
        modules[moduleName].isOnSideNav !== false
    )
    .map((moduleName) => ({
      name: moduleName,
      iconName: modules[moduleName].iconName,
      title: t(modules[moduleName].title),
    }));

  const getPanels = (layout: any): any => {
    if (!layout) return {};

    if (Array.isArray(layout)) {
      return layout.reduce((panels: any, layoutItem: any) => {
        return Object.assign(panels, getPanels(layoutItem));
      }, {});
    }

    return { [layout.name]: [], ...getPanels(layout.items) };
  };

  onLocalization("changed", () => {
    addLayout([], general.layout);

    store.dispatch(
      initialize({
        // layout: general.layout,
        language: langParm || general.language,
        direction: dir(),
        sideNavIcons,
        // panels: getPanels(general?.layout),
      })
    );
  });

  init(langParm || general.language, languages);
};

export default async () => {
  const [general, modules, styles, schemas, map] = await loadConfigs(
    "configs",
    ["general", "modules", "styles", "schemas", "map"]
  );

  const [env] = await loadConfigs("env", ["env"]);
  if (import.meta.env.VITE_TABLE_POC_STAGE === 'baseline') {
    delete modules['module-table-v8'];
    delete modules['module-table'];
  } else if (import.meta.env.VITE_TABLE_POC_STAGE === 'v8') {
    delete modules['module-table'];
  }
  const languages = await loadLanguages(general.availableLanguages);
  const devModeTopic = registerTopic("app", DEV_MODE_TOGGLED);

  setConfig({ env, general, modules, styles, schemas, languages, map });

  initLocalization();

  const devModeSubscriber = devModeTopic.subscribe(
    "dev-mode",
    (action: string, toggled: boolean) => {
      store.dispatch(setDevMode({ devMode: toggled }));
    }
  );
};

You normally do not need to rewrite startup. Understanding it helps diagnose "my module compiles but never appears."

Step 7: Know what Refresh does and does not simulate ​

The existing button is a valid full-snapshot rendering test. It verifies that table cells, ranges, and points update when a new dataset arrives.

It is not a real-time transport simulation:

Current behaviorNot covered by the button
Manual, complete snapshot replacementWebSocket/SSE/pub-sub delivery
Same record/task IDsInsert/delete events
Deterministic valuesOut-of-order sequence handling
One user action at a timeSustained bursts and backpressure
No connection lifecycleReconnect, unsubscribe, stale messages

The demo's revision + 1 is captured from the current render. Do not connect rapid asynchronous event delivery directly to that handler and assume it is a subscription implementation. Multiple events before a commit can reuse the same revision.

For a real stream, first decide whether the server sends snapshots or patches. Use a functional state update or reducer for related records/revision state, validate events at the boundary, and implement unsubscription and any sequence checks required by that protocol. This walkthrough deliberately does not invent a backend contract or claim to implement one.
