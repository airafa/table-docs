7. Verify behavior and troubleshoot ​

Step 1: Typecheck the actual table consumers ​

From the monorepo root:

sh
yarn tables:typecheck

This is the project's focused command, not a new test framework. Expected: the command finishes without TypeScript errors.

It does not guarantee every unrelated package in the monorepo is error-free, nor does it replace browser checks for custom-element lifecycle and canvas drawing.

Step 2: Build the application ​

sh
yarn build

Expected: Vite produces app/dist. The inspected dependency currently emits warnings about D3's unexported utcNice, and the app emits a large-chunk warning. Those are known limitations, not warnings this tutorial hides or claims to fix. If a new error appears, investigate it before proceeding.

Step 3: Install the browser binary if needed ​

The repository already uses Playwright. If Chromium is missing:

sh
yarn playwright install chromium

Do not install another browser automation framework.

Step 4: Run the development interaction check ​

sh
TABLE_POC_RUNS=1 yarn tables:runtime --dev both

The runner starts and closes its own Vite server and browser. You do not need a separate yarn dev server for it.

Step 5: Check the production build too ​

The production runtime runner serves a specific checkpoint directory. A normal yarn build writes app/dist, so build the matching checkpoint before running:

sh
yarn workspace @starterkit/app build --outDir ../artifacts/table-poc/both
TABLE_POC_RUNS=1 yarn tables:runtime both

Do not run the production browser command against old checkpoint files and assume you tested current source.

Reports are written to artifacts/table-poc/runtime-dev.json and artifacts/table-poc/runtime.json. Screenshots are saved there too. These are generated measurements, not required source changes for a tutorial. Review Git status before committing so local measurements are not included accidentally.

Step 6: Understand what performance numbers mean ​

text
user selects a new record count
  -> snapshot generation
  -> React render and commit
  -> custom-element property updates
  -> graph/layout/resize work
  -> animation frames and canvas drawing
  -> browser presentation

The table's React measurement covers only part of that chain. A small commit number cannot prove a responsive interaction.

The demo adds table-<version>-input-to-frame performance measures to capture more of the input path. In DevTools:

js
performance
  .getEntriesByType('measure')
  .filter(entry => entry.name.endsWith('-input-to-frame'))
  .map(entry => ({
    name: entry.name,
    durationMs: entry.duration,
  }));

The runner separately samples animation-frame gaps while dragging with both tables at 1,000 records. This is a more direct check of divider responsiveness than looking only at React timings.

Step 7: Check the documentation itself ​

sh
yarn docs:build
yarn docs:preview

The VitePress build resolves the complete-source includes and checks internal page links. Open the preview and verify:

  1. The homepage opens.
  2. The sidebar links to each of the seven chapters.
  3. Code blocks show actual source, not a literal include directive.
  4. Search finds GanttHeader and resizable.
  5. Narrowing the window exposes the mobile navigation.

The publishing workflow sets DOCS_BASE=/table-docs/ before building for GitHub Pages. Local builds default to /. Pushes to main automatically publish the generated site to the public repository; pull requests validate the build without publishing.

Troubleshooting checklist ​

The lc-gantt tag is present but empty ​

Check all of these:

js
customElements.get('lc-gantt');
customElements.get('lc-gantt-row');
customElements.get('lc-gantt-date-range');

Each should return a constructor, not undefined. Then inspect the element's properties, not just HTML attributes:

js
const chart = document.querySelector('.gantt-cell');
const row = chart.querySelector('lc-gantt-row');
console.log(chart.date_domain, chart.data, row.data);

Verify that dates fall in the visible domain and the chart width is nonzero. An array converted into an HTML string is not a valid data bridge.

"This name has already been registered" ​

You called customElements.define twice. Keep registration in the application's one-time browser startup path, not in every module or React component. Do not swallow this exception and pretend a different constructor was installed.

TypeScript cannot find v9 exports ​

Inspect the version resolved by the table workspace, not just the root:

sh
yarn why @tanstack/react-table

v8 and v9 have different setup APIs. Check the package manifest and keep the Vite optimization rules from chapter 1. Do not solve this by forcing one major for all workspaces.

The module compiles but does not appear ​

Check, in order:

  1. Root workspace patterns discover the package.
  2. app/package.json depends on the module workspace.
  3. moduleLoader.ts imports the configured module name.
  4. modules.json has init: true.
  5. Its container matches general.json's layout name.
  6. VITE_TABLE_POC_STAGE is not excluding it.

There is no separator ​

The panel needs resizable: true, exactly two modules, the option forwarded through Layout, and the panel/divider CSS. On viewports below 840px, hiding the separator is intentional.

The separator sticks with many records ​

Check the number of canvases:

js
document.querySelectorAll(
  '[data-table-version="v9.3.1"] lc-gantt-row',
).length;

In the standard demo viewport it should remain at most 20, not match 1,000. Check that the module passes rowHeight={49} and the renderer uses the shared window helper. Do not put setSplit on every pointermove; retain the animation-frame-coalesced CSS update.

The timeline grows but will not shrink ​

Check min-width: 0 on module/outer containers and contain: inline-size on header/row charts. Remove old fixed chart widths. A canvas's intrinsic size must not dictate the parent column's preferred width.

The expanding width went to the wrong column ​

The current CSS expands the last column. Timeline must stay last, or the renderer and selectors must be changed to target it explicitly.

Scrolling has gaps or misses records ​

Inspect actual tr[data-row-id] heights. Every data row must match rowHeight. Do not introduce multiline cells or a larger canvas without updating and revalidating the fixed-height windowing contract.

Header bins show old marks after resize ​

Keep the Summary-only key based on observed width and domain end. The package version inspected here does not fully clear obsolete bin drawings when its bin count shrinks. Do not randomize the keys of every row to hide this issue.

Refresh works but a subscription loses updates ​

Refresh is a manual full-snapshot test, not a stream implementation. The captured revision + 1 is not safe for multiple incoming events before React commits. Use protocol-specific event validation, functional updates/reducer, ordering, and cleanup before claiming real-time subscription support.

Finished ​

You now know where every moving part belongs:

  • The table workspace owns TanStack v9.
  • Browser startup owns custom-element registration.
  • React refs carry arrays and functions into lc DOM properties.
  • Module configuration puts two independent tables in one named container.
  • Native pointer events resize the container without a new DnD abstraction.
  • Table CSS gives Timeline the remaining width.
  • Shared dates and measured canvas widths preserve header/row alignment.
  • Windowing bounds rendering loops, and browser checks measure actual behavior.
