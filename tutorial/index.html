Table + Gantt 101 ​

Anonymized documentation

Company names, package names, custom-element tags, and URLs are placeholders throughout this guide, including imported code. Map them back to the real private dependencies before running examples. The application source has not been renamed.

This walkthrough explains how the implementation merged in PR #7 works and how to reproduce it in this starter kit. You do not need to know TanStack, custom elements, or the layout system before starting. Basic JavaScript and JSX will help.

Already using this checkout?

The application code below is already installed in the repository. Read it and run the checkpoints; do not paste second copies of registrations, modules, or config entries. When adapting another application, merge the relevant entries into its existing files instead of replacing its entire configuration.

What you will build ​

  • Two independent application modules: a TanStack v9 table and a v8 comparison.
  • Each table nested inside a real lc-gantt custom element.
  • A timeline column with Summary, BinPoint, Timeline, and FocusPointer in its header, not above the whole table.
  • Date ranges, milestone images, grid lines, and mouse actions in visible rows.
  • A 7/14/30/60/90-day selector and a button that replaces mock snapshots.
  • A separator that changes the modules' relative widths between 25% and 75%.
  • A timeline column that fills remaining space and repaints on resize.
  • Fixed-height windowing so thousands of records do not create thousands of continuously rendering canvases.

First understand the three boundaries ​

BoundaryResponsibilityNot responsible for
TanStack Table v9Records, columns, stable IDs, sorting, row modelCanvas drawing or module layout
@lc/graphsCustom elements, date-to-pixel scales, canvas drawing, chart eventsSorting the application's records
Application layoutCreates modules, arranges the panels, handles the width separatorComputing dates or table rows

The package name is @lc/graphs (plural), not @lc/graph. Gantt is an exported custom-element constructor, not a React component. After registration, JSX renders <lc-gantt>, not <Gantt />.

Why several lc-gantt elements? The header and cells need scales based on the timeline column's width, not the entire table's width. Separate charts share the same date domain and width. Putting one full-width axis above the table would include the ID/name/status columns in the scale and misalign dates.

How to use the code blocks ​

Small blocks explain one idea. Blocks marked complete source are imported directly from the implementation at documentation build time. They include imports and cleanup, not just fragments. Keep the shown file locations when copying: their relative imports depend on that structure.

The documentation site displays code; it does not execute the React app or register its browser-only custom elements during server-side rendering. Run the application separately with yarn dev to interact with the demo.
